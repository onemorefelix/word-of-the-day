# Англійська — довідка проєкту (CLAUDE.md)

Цей файл — повний контекст проєкту для продовження розробки в Claude Code. Поклади його в корінь репозиторію під назвою `CLAUDE.md` (Claude Code автоматично читає цей файл при старті) або `PROJECT.md`, якщо хочеш тримати назву нейтральною.

Розмова, в якій усе це обговорювалось і будувалось, лишається першоджерелом рішень — якщо тут чогось не вистачає або виникає сумнів у мотивації якогось рішення, звертайся туди.

---

## 1. Мета проєкту

Особистий застосунок для вивчення англійської мови, який вирішує три конкретні проблеми власника:

1. **Активний словниковий запас кульгає ситуативно** — людина може розмовляти англійською, але забуває конкретні слова в конкретних ситуаціях (наприклад, не пам'ятала як сказати "викидати сміття"), і плутається в часах (каже Present замість Past).
2. **Потрібен структурований шлях до IELTS** максимального рівня (Band 9) — це вимагає систематичного розширення активного словника до ~3000-4000 слів за тематичними категоріями.
3. **Базову граматику треба "закрити раз і назавжди"** — власник отримував пояснення часів багато разів різними способами і жодного разу це не закріпилось. Потрібне одне чітке, засноване на реальній частоті вживання пояснення, а не черговий переказ підручника.

**Побічна ціль:** для канадського громадянства потрібен мовний рівень **CLB 4** (Canadian Language Benchmark) — лише говоріння й слухання, читання/письмо не оцінюються. Це базовий рівень, який буде досягнутий задовго до завершення основного плану (орієнтир IELTS Band 7-9). Не потребує окремого фокусу чи звуження словника — просто нижчий поріг, який пройдеться "по дорозі". Приймаються результати IELTS General Training або CELPIP-General.

Некомерційний, персональний проєкт. Власник — розробник (Next.js/TypeScript/Supabase стек, має досвід із подібними інфраструктурними рішеннями по іншому проєкту — farm directory на PEI), тому архітектурні рішення тут навмисно прості (без бекенду, без фреймворків) — весь застосунок статичний HTML/CSS/JS, що деплоїться на GitHub Pages.

## 2. Як користувач буде це використовувати

- Мобільний телефон, встановлений як PWA ("Додати на головний екран")
- Основний режим — офлайн (застосунок кешується через service worker після першого відкриття з інтернетом)
- Прогрес зберігається виключно локально (`localStorage`), синхронізації між пристроями немає і поки не планується
- Розробка ведеться на ПК (раніше — через цей чат, тепер переноситься в Claude Code), тестування — на реальному телефоні через GitHub Pages

## 3. Поточна структура файлів

```
index.html                    — головний екран: список тем зі словами, вибір теми
trainer.html                   — тренажер карток (рушій інтервальних повторень), параметризований через ?topic=ID
grammar.html                    — список статей граматики (той самий патерн, що й index.html)
grammar-tenses.html              — стаття: часи (3 рівні за реальною частотою вживання)
grammar-articles.html             — стаття: артиклі a/an/the/нульовий артикль
grammar-prepositions.html          — стаття: прийменники часу in/on/at
reference.html                      — довідка: як читати IPA-транскрипцію + що означають частини мови

styles.css                            — єдина спільна таблиця стилів для всіх сторінок
app.js                                 — спільний JS-код (світлячки на фоні, реєстрація service worker, застосування розміру шрифту, індикатор прокрутки)
manifest.json                          — PWA-маніфест (іконка, назва, стартова сторінка)
sw.js                                   — service worker, керує офлайн-кешуванням
data/
  core.json                             — 51 базове слово (дієслова + побутова лексика), повний формат
  environment.json                       — пілотна тема IELTS "Environment", 25 слів, легший формат
fonts/
  fraunces-{400,600,700}.woff2            — заголовна серифна гарнітура
  plexmono-{400,500}.woff2                 — моноширинна (транскрипція, лейбли, кнопки)
  inter-{400,500,600}.woff2                 — основний текст
icon-192.png, icon-512.png                  — іконки PWA
```

Усі шрифти завантажені локально (через npm-пакети Fontsource) — жодної залежності від Google Fonts CDN, застосунок повністю офлайн-автономний з самого першого завантаження.

## 4. Дизайн-система

**Концепція:** "нічний кабінет алхіміка" — темно-чорнильний фон, фосфорно-бірюзове світіння, золото як воскова печатка. Свідомо відійшли від типових AI-дефолтів (кремовий фон + теракота, чи чорний + неон) — див. розділ 9 нижче про це рішення.

**Кольори (CSS-змінні в `styles.css`):**
```css
--ink:#ece6d8         /* основний текст, теплий білий */
--paper:#0c0e16        /* фон, глибокий чорнильно-синій */
--paper-deep:#05060a    /* найтемніший відтінок */
--moss:#5fb8ad           /* бірюзовий акцент — переклади, кнопка "Знаю" */
--gold:#c9a35d            /* золото — акценти, позначки частин мови, роздільники */
--rust:#8f3a3a              /* приглушений бордовий — кнопка "Забув" при наведенні */
--dim:#7d8699                 /* приглушений сірий — другорядний текст */
--line:rgba(236,230,216,0.11)  /* тонкі лінії-роздільники */
```

**Шрифти:**
- `Fraunces` (serif, ваги 400/600/700) — заголовки, слова, переклади
- `IBM Plex Mono` (400/500) — транскрипція, лейбли, кнопки, службовий текст
- `Inter` (400/500/600) — основний текст пояснень

**Розмір шрифту — масштабований.** Усі `font-size` в `styles.css` обгорнуті в `calc(Npx * var(--fs))`, де `--fs` — CSS-змінна, яку змінює `settings.html` (0.9 / 1 / 1.15 / 1.3) і зберігає в `localStorage` під ключем `basis_font_scale`. При додаванні нових стилів **завжди** пиши `font-size:calc(14px * var(--fs));`, а не просто `font-size:14px;` — інакше новий текст не буде масштабуватись налаштуванням шрифту.

**Фонова анімація:** три розмиті "плями" світла (blob-1/2/3), що повільно дрейфують, плюс частинки-"іскри" (`.firefly`), що піднімаються знизу вгору з мерехтінням. Все вимикається через `prefers-reduced-motion: reduce` для доступності.

**Навігація (`.tabbar`):** фіксована панель з 4 вкладками (Слова / Граматика / Довідка / Налаштування), присутня на кожній сторінці. Активна вкладка — золотий колір з крапкою-індикатором зверху. **Розташована вгорі, не внизу** (з 2026-08-27) — у мобільному браузері (не встановленому як PWA) нижня панель браузера з'їдала частину видимої висоти екрана й фіксована нижня навігація перекривала кнопки "Знаю"/"Забув" у тренажері. Клас лишився `.tabbar` попри назву, щоб не чіпати розмітку в кожному HTML-файлі.

## 5. Мовний стандарт (ЗАФІКСОВАНО 2026-08-27, ОБОВ'ЯЗКОВО дотримуватись у всьому новому контенті)

Власник живе в Канаді (PEI). Спочатку весь новий IELTS-контент (Environment/Education/Technology) писався британською вимовою (Cambridge/Oxford), бо ці джерела — загальновизнаний авторитет для граматики й ESL-конвенцій. Виявилось, що це не відповідає реальній меті: британська вимова не служить життю в Канаді, а сама IELTS приймає будь-який акцент носія на Speaking (британський, американський, канадський). Тому стандарт переглянуто.

**Вимова / IPA-транскрипція — General American**, не British RP. Канадська вимова лінгвістично підпадає під парасольку General American: ротична (чітко вимовляється "r" у всіх позиціях), дифтонг у "go" = `/oʊ/`, а не британське `/əʊ/`. Окремого усталеного онлайн-словника саме під канадську вимову з IPA нема — American English є найближчим практичним орієнтиром. Джерело: Wikipedia "North American English" + кілька лінгвістичних оглядів, що підтверджують — типова канадська вимова збігається з американською практично в усьому, де British/American відрізняються (є нюанси на кшталт Canadian raising в "about", але вони занадто дрібні для персонального застосунку).

**Орфографія — канадська, це змішана система, не "просто британська".** Джерело: офіційний стиль-гайд уряду Канади (our-languages.canada.ca) + Canadian Oxford Dictionary як головний авторитет (при варіантах — перша форма в словнику):
- `-our`, `-re`, `-ce` — британський варіант: **colour** (не color), **centre** (не center), **defence** (не defense)
- `-ize`, `-ization` — **американський** варіант, НЕ британське `-ise`: **organize**, **organization** (не organise/organisation). Це не інтуїтивно — легко припустити "раз усе інше британське, то й це теж", але урядовий стиль-гайд explicitly каже protии -ise.
- Подвоєння приголосної перед суфіксом — британський варіант: **travelling**, **cancelled** (не traveling/canceled)
- Окремі слова без системного правила, лише конкретні приклади (за офіційним стиль-гайдом): **program** (не programme — з 2026-08-27 уряд Канади сам перейшов на це написання), **cheque** (не check, у фінансовому сенсі), **tire** (не tyre), **connection** (не connexion). Джерело: те саме our-languages.canada.ca. Якщо трапляється слово поза цим списком і поза правилами вище — вважати "consistency important, pick a pattern" (сам стиль-гайд це визнає) і обирати за аналогією до вже задокументованих прикладів

**Джерела для перевірки лишаються ті самі** (Cambridge Dictionary / Oxford Learner's Dictionaries / British Council) для значень слів і граматичних правил — вони нейтральні щодо варіанту англійської. Але коли є вибір між американським/британським варіантом транскрипції чи написання — завжди обирай американську вимову + канадську орфографію (за правилами вище).

**Довідка (`reference.html`)** навчає американської вимови — таблиця дифтонгів/голосних перебудована під ротичну модель: нема окремих "центруючих" дифтонгів (ɪə/eə/ʊə — тут/hair/tour), бо в American English це голосний + r; ɜː → ɝ (bird); ɒ зникає як окремий звук — зливається з ɑː (hot і cot вимовляються з тим самим голосним, що car).

## 6. Архітектурні рішення і чому саме так

### 6.1 Без бекенду, без фреймворків
Увесь застосунок — чистий HTML/CSS/vanilla JS. Причина: масштаб проєкту (особистий інструмент, не продукт для інших користувачів) не виправдовує складність React/Vue чи серверної частини. GitHub Pages безкоштовно хостить статичні файли — цього достатньо.

### 6.2 Дані тем — окремі JSON-файли, не вшиті в код
`data/core.json`, `data/environment.json` (і майбутні теми) — окремі файли, завантажуються через `fetch()` з `trainer.html`. Причина: при масштабуванні до 2500-4000 слів (15 тем) один величезний JS-масив у коді був би неможливим для підтримки й редагування. Окремі файли також дають service worker'у змогу кешувати їх незалежно.

**Важливий технічний нюанс:** `fetch('data/core.json')` **працює тільки при відкритті через http(s)-сервер** (GitHub Pages чи `python3 -m http.server` локально), НЕ при відкритті файлу подвійним кліком (`file://`). Той самий принцип, що й з `manifest.json` раніше. Для локальної розробки в Claude Code запускай локальний сервер:
```bash
python3 -m http.server 8000
# відкрити http://localhost:8000 у браузері
```

### 6.3 Прогрес — localStorage, окремо по темах
Ключ зберігання: `basis_progress_{topicId}` (наприклад `basis_progress_core`, `basis_progress_environment`). Кожна тема має власний ізольований прогрес, теми не змішуються. Формат: `{ "wordId": { "box": 1-5, "next": timestampMs } }`.

**Чому окремо по темах, а не один спільний об'єкт:** якщо колись знадобиться скинути прогрес однієї теми, не займаючи інших, чи видалити тему — це просто видалення одного ключа localStorage.

### 6.4 Інтервальні повторення — спрощений алгоритм (не повний SM-2)
Файл: логіка в `trainer.html`, функції `answer()`, `buildQueue()`.
- 5 "боксів" (box 1-5), кожному відповідає інтервал: 1, 3, 7, 14, 30 днів (`INTERVALS_DAYS` масив)
- "Знаю" → box+1 (максимум 5), "Забув" → box скидається на 1
- Слово вважається "вивченим" (mastered) при box ≥ 5
- Черга показу: спочатку прострочені повторення (сортовані за датою), потім нові слова

Це навмисно простіше за справжній алгоритм SuperMemo (SM-2), яким користується Anki — для персонального використання зайва складність (easiness factor, тощо) не виправдана.

### 6.5 Service Worker — network-first для HTML і даних, cache-first для статики
**Історія проблеми:** початкова версія кешувала все "cache-first", через що оновлення коду не з'являлись без Ctrl+Shift+R (примусове очищення кешу браузера).

**Поточне рішення** (`sw.js`):
- HTML-сторінки (`.html`) і файли даних (`/data/*.json`) — спочатку йде мережевий запит за свіжою версією, кеш використовується лише як резерв при відсутності інтернету
- Шрифти, іконки, `styles.css`, `manifest.json` — кеш спочатку (ці файли рідко змінюються)

**Правило на майбутнє:** щоразу, коли редагуєш `sw.js` (додаєш новий файл у `SHELL`) **або `styles.css`/`app.js`** (кешуються cache-first, тож старий кеш інакше не побачить оновлення), **обов'язково піднімай номер `CACHE_NAME`** (зараз `basis-v10`) — інакше старий кеш не очиститься і зміни не підхопляться навіть з network-first стратегією для нових файлів, яких ще нема в старому кеші.

### 6.6 Один спільний styles.css, один app.js
Після першої ж спроби зробити другу сторінку стало зрозуміло, що дублювати ~400 рядків CSS у кожному HTML-файлі — це прямий шлях до розсинхронізації стилів. Тому:
- **Ніколи не додавай `<style>` блок з дублюючими правилами** в новий HTML-файл — тільки `<link rel="stylesheet" href="styles.css">`, і за потреби невеликий `<style>` блок ТІЛЬКИ зі стилями, унікальними саме для цієї сторінки (приклад: `.ipa-grid` в `reference.html`)
- Аналогічно `app.js` містить логіку, потрібну на кожній сторінці (світлячки, service worker, шрифт) — підключай його через `<script src="app.js"></script>`, не копіюй логіку inline

## 7. Формати даних (схеми)

### 7.1 `data/core.json` — повний формат (для дієслів з часовими формами)
```json
{
  "id": "throw_away",
  "en": "throw away",
  "ph": "/θroʊ əˈweɪ/",
  "uk": "викидати (сміття)",
  "pos": "verb",
  "forms": {
    "base": "throw away", "phBase": "/θroʊ əˈweɪ/",
    "past": "threw away", "phPast": "/θruː əˈweɪ/",
    "part": "thrown away", "phPart": "/θroʊn əˈweɪ/"
  },
  "examples": [
    ["Present Simple", "I throw away the trash every evening."],
    ["Past Simple", "I threw away the trash yesterday."],
    ["Present Perfect", "I've already thrown away the trash."]
  ],
  "note": "Пояснення з <b>HTML-тегами</b> для виділення жирним."
}
```
`forms` — тільки для дієслів. `examples` — масив пар [назва часу, речення], зазвичай 3 (Present Simple / Past Simple / Present Perfect).

### 7.2 `data/environment.json` та майбутні тематичні файли — легкий формат (іменники/прикметники)
```json
{
  "id": "environment_sustainable",
  "en": "sustainable",
  "ph": "/səˈsteɪnəbl/",
  "uk": "сталий, екологічно стійкий",
  "pos": "adjective",
  "example": "The company switched to sustainable packaging last year.",
  "example2": "Governments are under pressure to adopt more sustainable policies.",
  "note": "Ключове слово IELTS-есе. Колокація: <b>sustainable development</b>."
}
```
Без `forms` (нема часових форм у прикметників/іменників). `example` + `example2` — два речення замість трьох по часах. `note` фокусується на колокаціях і типових помилках, а не на граматичних формах.

**`trainer.html` автоматично розрізняє формати** — перевіряє наявність `item.examples` (повний формат) чи `item.example` (легкий формат) і рендерить відповідно. Це означає, що нову тему можна додавати в будь-якому з двох форматів без зміни коду тренажера.

### 7.3 Реєстр тем — де прописується нова тема
Тему потрібно зареєструвати у **двох місцях**:

1. `index.html`, масив `TOPICS`:
```js
{
  id:"education",
  name:"Education",
  desc:"Короткий опис теми українською.",
  file:"data/education.json",
  tag:"IELTS"  // або null, якщо це не IELTS-тема
}
```

2. `trainer.html`, об'єкт `TOPIC_META`:
```js
education: { name:"Education", file:"data/education.json" }
```

Забудеш другий пункт — тема відкриється на домашньому екрані, але клік по ній не завантажить дані в трейнері (буде помилка "Немає з'єднання", бо `TOPIC_META[id]` буде `undefined` і впаде на дефолтний `core`).

### 7.4 Конвенція іменування id

**Прийнята практика (з 2026-08-27):** id тематичних слів префіксуються назвою теми, наприклад `environment_sustainable`, `education_curriculum`. `environment.json` вже мігровано на цю конвенцію. `core.json` лишається без префіксу (`throw_away`, а не `core_throw_away`) — це базовий список, а не тематичний, колізій з майбутніми темами там не буде.

**Чому саме зараз:** дешевше мігрувати id, поки тем тільки дві, ніж чекати до 15 тем. **Побічний ефект зміни id в existing темі:** прогрес у `localStorage` (`basis_progress_environment`) прив'язаний до старих id — після цієї міграції прогрес по темі Environment на пристроях, де вона вже проходилась, обнуляється (старі ключі більше не збігаються з новими id). Для нових тем (Фаза 2 і далі) це вже не проблема — вони одразу створюються з префіксованими id.

## 8. Джерела істини — як перевіряти контент (ОБОВ'ЯЗКОВО)

Власник явно наголосив: **уся інформація має бути справжньою, звіреною з авторитетними джерелами, а не згенерованою з пам'яті**. Це правило застосовується до кожного нового шматка контенту — граматики, визначень слів, транскрипції, IELTS-специфіки.

### 8.1 Граматика (часи, артиклі, прийменники, майбутні теми)
- **Cambridge Dictionary — English Grammar Today** (dictionary.cambridge.org/grammar) — основне джерело, використане для статей про артиклі й прийменники
- **British Council LearnEnglish** (learnenglish.britishcouncil.org) — друге за пріоритетом, особливо для прикладів вживання
- **Oxford Learner's Dictionaries** (oxfordlearnersdictionaries.com) — альтернативне/додаткове джерело для звірки

### 8.2 Частота вживання граматичних форм (як у статті про часи)
- Спиратись на корпусні дослідження (Corpus of Contemporary American English, чи опубліковані аналізи на кшталт того, що використали для розподілу часів на 3 рівні — джерело: аналіз Крамського/Krámský, що показує ~96% розмовної англійської в 5 з 12 часів)

### 8.3 IPA-транскрипція
- **Cambridge Dictionary** чи **Oxford Learner's Dictionaries** — обидва мають озвучені словникові статті з коректним IPA для кожного слова

### 8.4 Визначення слів і приклади речень
- Словникові джерела (Cambridge, Oxford, Merriam-Webster) для точності значення
- Приклади речень можна писати самостійно (не копіювати дослівно з словника — це і авторське право, і потрібен контроль над рівнем складності), але значення слова в реченні має відповідати словниковому

### 8.5 IELTS-специфічний контент
- **Офіційні джерела:** ielts.org, British Council, IDP (це організації, які проводять сам іспит)
- **Навчальні ресурси для тематичної лексики:** IELTS Liz, IELTS Material, IELTS Jacky — це усталені ресурси, що роками збирають лексику саме під формат іспиту (Part 1/2/3 у Speaking, Task 1/2 у Writing)
- Теми IELTS доволі стабільні рік у рік (Environment, Education, Technology, Health, Work, Crime, Government, Globalization, Travel, Family, Food, City, Money, Sport, Science) — це вже підтверджено крос-референсом кількох джерел у попередній розмові

### 8.6 Процес перевірки нового контенту
Перш ніж додавати новий блок контенту (стаття граматики, нова тема слів, IPA для нового слова):
1. Пошук через `web_search` для перевірки факту/правила
2. За потреби `web_fetch` для читання повної статті з авторитетного джерела
3. Писати контент своїми словами на основі перевіреного факту (не копіювати дослівно — авторське право)
4. Якщо джерела суперечать одне одному чи інформація неоднозначна — краще позначити це прямо в тексті статті ("деякі джерела вважають...", "залежить від діалекту"), ніж видавати одну версію за абсолютну істину

4. **Локальні шрифти замість Google Fonts CDN** — для повної офлайн-роботи (застосунок мав відкриватись навіть без інтернету, включно зі шрифтами)
5. **Дизайн-тема пройшла два етапи:** спочатку "лісовий" (мох, зелень, PEI-вайб), потім за проханням власника перероблена на "нічний кабінет алхіміка" (чорнильно-синій, бірюзове світіння, воскова печатка) — свідомий відхід від типових AI-дизайн-дефолтів (кремовий+теракота чи чорний+неон). Стара однофайлова версія з лісовою темою (`basis.html`) видалена 2026-08-27 як мертвий артефакт — лишилась тільки в git-історії.
6. **Багатофайлова архітектура (замість одного HTML-файлу)** — введена, коли стало зрозуміло, що масштабування до 15 тем і 2500-4000 слів неможливе з одним вшитим масивом
7. **Навігація перероблена на постійну нижню панель** — після того, як власник (і будь-хто на його місці) не міг зрозуміти, де перемикання між темами й граматикою, коли це були маленькі приглушені посилання в кутку
8. **Навігація перенесена з низу нагору** (2026-08-27) — у мобільному браузері (не встановленому на домашній екран) фіксована нижня панель перекривала кнопки "Знаю"/"Забув" у тренажері, бо панель браузера з'їдала частину видимої висоти. Позиція (верх/низ), а не сам факт постійної видимої панелі, була причиною попередньої проблеми з п.7 — тому цей відкат не суперечить попередньому рішенню
9. **Кнопки продовжували "падати" нижче екрана і після п.8** (2026-08-27, той самий день) — виявилось дві окремі причини: (а) `body`-padding зріс на 32px сумарно (100+60=160 замість старих 32+96=128), коли навігація переїхала нагору, а магічне число в `.stage{max-height:calc(100vh - 260px)}` лишилось старим і не врахувало цю різницю; (б) `100vh` на мобільному браузері рахується як висота БЕЗ панелі браузера, тому реальна видима висота менша за номінальний `100vh`. Виправлено: число підняте на ті самі 32px (260→292, 230→262 у медіа-запиті для вузьких екранів) + додано `100dvh` другим рядком (динамічна висота, враховує фактичну видиму область; де браузер її не підтримує — просто ігнорує рядок і лишається на `vh`). **Урок:** ці два магічні числа (`.stage` max-height і сумарний `body` padding) залежать одне від одного, але живуть в різних правилах CSS — при будь-якій зміні одного з них треба звірити і друге
10. **У довідці (`reference.html`) свідомо не використовується кирилична "приблизна вимова" для IPA-символів** (2026-08-27) — обговорено з власником: жодна українська буква не передає англійські æ/ʌ/ɜː/ə/θ/ð чесно (цих звуків просто нема в українській), і кириличний "замінник" ризикує закріпити саме той акцент, який застосунок покликаний виправити. Замість цього — англійське слово-приклад (як роблять Cambridge/Oxford) + мінімальні пари (ship/sheep, full/fool, bad/bud, hot/heart) для звуків, які плутаються найчастіше. Приголосні, що мають чесний український аналог (ʃ≈ш, ʒ≈ж, tʃ≈ч, dʒ≈дж), теж навмисно без кирилиці — для послідовності методу
11. **Мовний стандарт змінено з British на American English** (2026-08-27) — весь IELTS-контент (Environment/Education/Technology) спочатку писався британською вимовою (Cambridge/Oxford), бо це загальновизнані ESL-джерела. Виявилось, що це не відповідає реальній меті проєкту: власник живе в Канаді, а канадська вимова лінгвістично ближча до General American (ротична, `/oʊ/` замість `/əʊ/`), не до British RP. IELTS до того ж приймає будь-який акцент носія на Speaking. Рішення: вимова — American, орфографія — канадська (змішана система: `-our/-re/-ce` британські, але `-ize/-ization` — американські, підтверджено урядовим стиль-гайдом Канади, а не інтуїтивним припущенням "усе британське"). Деталі й джерела — розділ 5. Це означало ретроактивну конвертацію вже написаного контенту (Environment 75 слів + Education 25 + Technology 25 = 125 слів) і повну переструктуризацію таблиці IPA в `reference.html` під ротичну модель — зроблено того ж дня. Виявилось, що конвертація не чисто механічна: не можна просто замінити символи (əʊ→oʊ, ɒ→ɑː) — треба щоразу дивитись на написання слова, чи є там "r" після голосного (перед приголосною/в кінці слова — вимовляється в американській; між двома голосними — вимовляється однаково в обох акцентах, міняти нічого не треба). Окрема категорія — слова, де британська й американська відрізняються не голосним, а наголосом (напр. "migrate" BrE /maɪˈɡreɪt/ vs AmE /ˈmaɪɡreɪt/) — такі звірялись індивідуально, а не виводились правилом. Заодно виявлено й виправлено: (а) оригінальний 25-слівний пілот Environment (до цієї сесії) вже був сам собою непослідовним сумішем British/American в межах одного слова (напр. "conservation" мало британський голосний ɒ і американське родиче r одночасно); (б) кілька випадків "e" замість "ɛ" для DRESS-голосного, пропущених при першому проході конвертації — знайдено повторним автоматизованим скануванням, не візуальним переглядом

## 11. Як тестувати локально в Claude Code

Оскільки `fetch()` до `data/*.json` не працює з `file://`, для будь-якої розробки, що включає завантаження даних тем, потрібен локальний сервер:

```bash
cd /шлях/до/проєкту
python3 -m http.server 8000
```
Відкрити `http://localhost:8000` у браузері. Це також дозволяє тестувати service worker і PWA-маніфест коректно (хоча "Додати на головний екран" краще перевіряти вже на реальному хостингу з https, деякі браузери вимагають https для повноцінної PWA-інсталяції).

**Після кожної зміни в `sw.js` не забувати:**
1. Підняти `CACHE_NAME` (`basis-v10` → `basis-v11` тощо)
2. При тестуванні в браузері — DevTools → Application → Service Workers → Update on reload (щоб не боротись зі старим кешем під час розробки)

## 12. Деплой на GitHub Pages

1. Репозиторій вже створено й ініціалізовано: **`onemorefelix/word-of-the-day`** на GitHub, remote `origin` налаштований, локальні коміти вже є. Поточна розробка ще не залита в remote — це нормально, заливай, коли будеш готовий: `git push origin master`.
2. Settings → Pages → Source → Deploy from branch → main / (root)
3. Сайт з'явиться на `https://{username}.github.io/{repo-name}/`
4. `start_url` в `manifest.json` вказує на `./index.html` — має працювати автоматично, якщо репозиторій структурований як є (усі файли й папки `data/`, `fonts/` в корені)
5. Домен (pp.ua) — свідомо відкладено власником ("поки не буду ставити"), можна додати пізніше через CNAME без зміни коду
