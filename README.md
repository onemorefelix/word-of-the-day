# Базис — масштабована версія (пілот)

Це демонстрація архітектури "у масштабі": домашній екран з категоріями, окремі файли даних по темах, і сторінка граматики. Зроблено як пілот з однією тестовою темою (Environment, 25 слів), щоб оцінити формат перед тим, як наповнювати решту 14 тем.

## Структура файлів

```
index.html          — домашній екран: список тем з прогресом
trainer.html         — тренажер карток (той самий рушій повторень, тепер параметризований темою)
grammar.html          — довідник граматики: три рівні часів за реальною частотою вживання
styles.css            — спільна тема для всіх сторінок (кольори, шрифти, анімації, компоненти)
manifest.json         — PWA-маніфест
sw.js                 — service worker (кешування офлайн)
data/
  core.json           — 51 базове слово (дієслова + побут), повний формат з формами часів
  environment.json     — пілотна тема IELTS, 25 слів, легший формат
fonts/                — локальні шрифти (Fraunces, IBM Plex Mono, Inter)
icon-192.png, icon-512.png — іконки PWA
```

## Що нового порівняно з попередньою версією

**Домашній екран (`index.html`)** — замість одразу відкривати картки, тепер список тем. Кожна тема показує: скільки слів на повторення сьогодні, скільки всього слів, прогрес-бар вивченого. Клік по темі відкриває `trainer.html?topic=ID`.

**Параметризований тренажер (`trainer.html`)** — той самий рушій інтервальних повторень (localStorage, box/next), що й раніше, але тепер:
- Завантажує слова через `fetch('data/ID.json')` замість вшитого масиву в коді
- Прогрес кожної теми зберігається окремо (`basis_progress_core`, `basis_progress_environment` тощо) — теми не змішуються
- Підтримує два формати карток: повний (з формами дієслів і трьома прикладами по часах — для `core`) і легкий (одне речення + примітка про колокацію — для тематичної лексики)

**Сторінка граматики (`grammar.html`)** — поки одна стаття: три рівні англійських часів за реальною частотою вживання в розмовній мові (дослідження показують, що ~96% розмовного мовлення вкладається лише в 5 із 12 часів). Це шаблон для майбутніх статей — артиклі, прийменники, фразові дієслова.

**Спільні стилі (`styles.css`)** — винесено з окремих HTML-файлів, бо дублювати ~400 рядків CSS у кожній з 15+ майбутніх тем було б неможливо підтримувати.

## Важливий технічний нюанс

`fetch('data/environment.json')` **працює тільки на реальному хостингу** (GitHub Pages чи будь-який https-сервер), а не при відкритті файлу подвійним кліком з диска (`file://`) — так само, як раніше було з `manifest.json`. Це нормально, враховуючи твій план (заливати на GitHub Pages і ставити PWA на телефон) — просто май на увазі, якщо колись схочеш перевірити щось локально: знадобиться `python3 -m http.server` чи подібний локальний сервер, а не простий подвійний клік.

## Що ще варто доробити перед повним масштабуванням до 15 тем

1. **Формат "легкої" картки для тем ще сирий.** Зараз у Environment немає прикладів у різних часах (тільки одне речення), бо це переважно іменники/прикметники. Варто вирішити: чи достатньо одного речення, чи додати друге для складніших випадків.

2. **Колізії id між темами.** Прогрес зберігається окремо per-topic, тому технічно це не ламається, але варто мати конвенцію на кшталт `environment_mitigate`, щоб уникнути плутанини при перегляді коду.

3. **Немає індикатора "ця тема ще не заповнена".** Коли будемо додавати теми поступово, треба показувати на домашньому екрані статус "скоро" для тем, яких ще нема.

4. **grammar.html поки одна стаття.** Структуру продумано так, щоб додавати нові статті (артиклі, прийменники) було просто копіюванням блоку — але навігація між статтями в межах сторінки ще не зроблена.

5. **sw.js треба оновлювати вручну щоразу, коли додається нова тема** — новий `data/*.json` файл варто дописувати в список `SHELL` для кешування про запас офлайн.

## Розміщення на GitHub Pages

Той самий принцип, що й раніше — заливаєш усю структуру папок як є (зберігаючи `data/` і `fonts/` підпапками), вмикаєш Pages, `start_url` в маніфесті вже вказує на `index.html`.
